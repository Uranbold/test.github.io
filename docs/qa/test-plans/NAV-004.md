## 1. Scope

In scope: all 54 acceptance criteria; the reference route set RS1–RS8 live; the story edge cases that apply to a
preview (location off/denied/unavailable/stale, no network, gateway down, 429 with and without a readable
`Retry-After`, no route, out of coverage, too far on foot/bike, origin = destination, out-of-order responses, fast
tab switching, language and theme switch with a route, very long intercity turn lists, ETA across midnight,
roundabout without exit, unknown manoeuvre types, zero-width characters in street names); the static public build
(D44); design hooks requested by UX (Tab order, turn list as one Tab stop, state precedence, test ids) and the
architect (walk/bike without `costing_options`, bearing 360, `continue` + turning modifier, RS8 = P1 → X2 on foot).

**RS8 definition used:** P1 → X2 **on foot** (ADR-0008 §4, architect and mobile handoffs): P1 → X1 on foot is ~245 km
straight line, under the 250 km dev walk limit, and returns 200. The original P1 → X1 walk is recorded as **RS8a**.

Out of scope (story): active guidance, voice, off-route and **reroute** (NAV-005), so **no GPX fixtures** are added
(a preview has no position trace to replay); native apps; Safari/iOS, Firefox/Edge (automated runs are Chromium only,
D14); battery/CPU drive (no guidance session). Tests of other stories are **not changed** (story Test approach,
coordination rule 3); AC 42 runs them unchanged.

### Simulation (browser only, story Test approach)
- `page.route('**/v1/route**')` (POST only): fixture OSRM bodies with 1–3 routes, snap distances, 400 `NoRoute`,
  `NoSegment`, `DistanceExceeded`, `InvalidOptions`, `InvalidValue`, `TooBig`, unknown code, `ValhallaError` 171 and
  170, non-JSON 400, 413, 429 with `Retry-After: 3`, missing, `abc`, `0`, an HTTP date (→ 5 s), 502/503/504, network
  abort, connection refused, **CORS failure** (a mismatched `Access-Control-Allow-Origin`), no answer (12 s client
  timeout), unparsable 200, 200 without routes, delayed (1 s, 1.5 s, 2.5 s, 6 s) and out-of-order responses.
- `context.setOffline()`; Playwright geolocation (granted fix, `null` → `POSITION_UNAVAILABLE`, not granted → denied);
  `emulateMedia({ reducedMotion: 'reduce' })`; `page.clock` (install, `pauseAt`, `runFor`) for AC 25 and a stale fix.
- Reverse lookups of coordinate cards are mocked in every NAV-004 test (they are NAV-003 behaviour, not under test).

**Timing method.** Times are measured in the page (`performance.now()`), from the activation event (click/keydown
captured in the capture phase) to the first DOM state observed by a MutationObserver, or to MapLibre
`movestart`/`moveend`. Playwright round trips are never counted. Camera budgets use the response arrival as the
start (stricter than "render"), because a reduced-motion jump runs in the same task as the render.

**SwiftShader note.** Software WebGL keeps the main thread busy for 300–1,400 ms after each route render, so real
Playwright key presses arrive far apart. AC 11 "two ArrowRight within 300 ms" therefore dispatches both keydowns in
the page 100 ms apart (busy wait); a real key press checks the same handler elsewhere (AC 45 tabs test).
