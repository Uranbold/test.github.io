## Bug B-NAV019-01: demo app crashes instantly on open (PO report 2026-10-04)

- **Report:** Xiaomi Redmi Note 8 Pro (Helio G90T, arm64-v8a, MIUI 11–12.5, Android 9–11). The demo APK «Туршилтын горим» from commit 763bd4e installs, then crashes as soon as it is opened.
- **Severity (QA, §3.4):** S1 (confirmed at verification; PO priority P1 → bug lane, top). The matrix lists "app crashes on start" as S1. Triage proposed S2. The crash hits every device and API level, not only this phone. It is limited to the `demo` build type (debug and release do not run the code), and no release has shipped.
- **Owner:** mobile-engineer (`mobile/android/app/src/demo/java/mn/navmn/app/demo/DemoVariant.kt`).
- **Root cause (reproduced):** `NavApplication.onCreate` calls `DemoVariant.onApplicationCreate` (`DemoVariant.kt:79`), which calls MapLibre's `HttpRequestUtil.setOkHttpClient(...)`. The chain then runs `HttpRequestImpl.<clinit>` → `HttpIdentifier.getIdentifier()` → `MapLibre.getApplicationContext()` → `validateMapLibre()`, which throws `MapLibreConfigurationException`. Nothing has called `MapLibre.getInstance` at that point; `NavMap` only calls it later. The result is an `ExceptionInInitializerError` in `Application.onCreate`, so the process dies before the first Activity.
- **Steps to reproduce:**
  1. Build the demo APK: `./gradlew :app:assembleDemo -Pnav.demoTilesFile=<pmtiles>`.
  2. Install it on any Android 8–15 device.
  3. Open «Туршилтын горим».
- **Expected:** the route picker is shown over the map within 2 s (AC 6).
- **Actual:** the app closes at once (process crash in `Application.onCreate`).

**Constraint for the fix,** so that TC-B19-01/02 pass unchanged: the demo `Application.onCreate` must not touch MapLibre at all. `MapLibre.getInstance` calls native code (`TileServerOptions.mapLibreConfiguration`), and that native code does not exist on the host JVM. Moving `getInstance` into `onCreate` would replace the crash with an `UnsatisfiedLinkError` in the JVM test. Configure MapLibre's HTTP client right after `MapLibre.getInstance` in `NavMap`, before the first `MapView` exists. This keeps ADR-0016 §7 intact, because no MapLibre request can come before that point. A scratch experiment with the call moved out of `onApplicationCreate` passed 6/6.

**Run:**

- `python3 tests/android/nav019/demo_apk_startup_checks.py --apk <demo.apk>`
- `./gradlew :app:testDemoUnitTest --tests 'mn.navmn.app.qa.QaNav019DemoStartupTest' -Pnav.demoTilesFile=<pmtiles>`

The Gradle command needs the demo unit-test variant. Since the NAV-005 section N fix loop (2026-10-04, NAV-005 test plan §8 Q9, option a) the variant exists only when `-Pnav.demoTilesFile` is set (file mode, which TC-B19-02 asserts); without it `./gradlew test`, `check` and `build` have no `testDemoUnitTest` and need no demo property. The variant compiles (the `buildSrc` guard is on the `testDemo` source set, ADR-0016 known gap 8) and runs only the classes in `src/testDemo` (today `QaNav019DemoStartupTest`), not the whole `src/test` suite; it is disabled if `src/testDemo` is empty. Guarded statically by NAV-005 `static_checks.py` TC-S35. `--tests` is optional: `./gradlew :app:testDemoUnitTest -Pnav.demoTilesFile=<pmtiles>`.

### Verification of the fix (2026-10-04, QA)

Fix by mobile-engineer: the demo no longer calls MapLibre in `Application.onCreate`. `ReplayVariant.onMapLibreInitialised()` (no-op default) is called by `NavMap` right after `MapLibre.getInstance` and before the first `MapView`; `DemoVariant` sets MapLibre's HTTP client there (ADR-0016 §7). Plus a crash-report diagnostic in debug and demo builds (`BuildConfig.CRASH_DIAGNOSTICS`, `log/CrashLog.kt`, `ui/screens/CrashReportScreen.kt`).

Both regression tests ran **unchanged** (sha256 of `QaNav019DemoStartupTest.kt` `10fdea8d…0e60` equals the copy used for the 763bd4e reproduction; `demo_apk_startup_checks.py` `97d4aebf…fb54` predates the fix). All runs were on a frozen copy of the working tree, so the concurrent NAV-005 edits could not change files mid-run (the tree was compared with the copy afterwards: identical).

**Gap noted (no automated guard yet):** nothing in the JVM suite asserts that `NavMap` calls `ReplayVariant.onMapLibreInitialised()` before the first `MapView` (ADR-0016 §7 network block of the demo). `NavMap` needs MapLibre native code, so a JVM test is not possible; checked by hand in the dex above. Planned: TC-B19-11, a dex-order check in a separate script, so `demo_apk_startup_checks.py` stays unchanged as the regression test.
