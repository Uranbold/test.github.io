## 1. Scope

In scope: all 49 AC at the level this environment allows; R1 (G1, car), R2 (G5, walk), R3 (G8, car, two rotaries),
G4 (test-only arrival track); the story edge cases that can be simulated: no Mongolian voice (iPhone-like voice list
with English voices only), no voice at all, a voice list that fills late (`voiceschanged`), speech error, mute and
reload, language switch mid-prompt (both directions), page hidden (Safari tab/app switch, lock), track end without
arrival, «Дуусгах» mid-prompt, double tap on «Эхлэх», network loss mid-replay, theme switch and rotation, wake lock
granted / refused / missing, route data 404 / 500 / HTML / slow, the public demo folder without credentials (D107/D116:
200, no auth challenge, `noindex` served), two folder names and two levels of depth, the public site next to the demo
folder.

Out of scope (story): reroute, GPS loss and accuracy simulation, speeds other than 1×, cloud voices, deployment
automation, NAV-005 Android behaviour (golden file only as the cross-platform oracle).

**Not testable here (AC 48, real iPhone; checklist in `web/README.md` › Demo mode › Real-iPhone checklist):** that the
page opens without a password prompt and the 200 (without credentials) / `noindex` / 206 checks on the PO's host;
tiles over HTTP Range on the real host (R6);
whether iOS has a Mongolian voice; real speech and chime audibility (ring/silent switch off and on); that audio starts
without an extra tap after «Эхлэх» in real Safari; screen staying on for R3 (787 s); pause after locking the phone;
real safe areas, the Safari toolbar, the aA text size, rotation and VoiceOver; the iOS version.

Additions requested by UX for the real-iPhone checklist (all already in the README list as items 8–10): the Safari
toolbar never covering «Эхлэх», «Дуусгах» or the attribution; landscape safe areas; aA text size at 200 %; a pinch on
the banner not zooming the page; audio resuming after a phone call or Control Centre; VoiceOver announcing each
instruction once. The design target excludes 375×548 (Safari toolbars shown on a 375 px iPhone) at 200 % text (UX
known limitation 1); it is not tested.

### Simulation and oracles
- **Clock:** `page.clock.install()` then `pauseAt()` **before** navigation (README note), so page time advances only
  through `runFor()`. Replays run at fake time; one replay second costs about 0.2 s of wall time with the map canvas
  not painted (`visibility: hidden`, layout unchanged) in the logic replays; layout and rendering tests paint it.
- **Voice lists:** `['mn-MN', 'en-US']` (a Mongolian voice exists), `['en-US', 'en-GB']` (iPhone-like: no Mongolian),
  `['en-GB', 'en-US']` (en-US must be preferred), `[]`, late list (fires `voiceschanged` after 500 ms).
- **Cross-platform oracle (AC 26):** `tests/gpx/nav005/golden/voice-golden.tsv`, compared **exactly** (text sequence)
  with ± 2 s on start times, never relaxed. Its currency was checked: Android `QaGpxReplayTest.tcR13` (which
  `assertEquals` the regenerated set against the file) passes on the current Android code.
- **Independent oracle:** QA's `RouteOracle` from the fixtures (not from `web/src`): stated distance vs true remaining
  distance, prompt before each car manoeuvre at 20–250 m, no prompt for a passed manoeuvre, banner = AC 27 text of the
  next manoeuvre, banner distance and street, remaining time and distance (AC 21 formula), arrival.

## 3. How to run

```bash
cd tests/e2e
./nav017/run.sh                                         # build, site, Chromium + WebKit (Docker), stop
NAV017_ENGINES=chromium ./nav017/run.sh replay.test     # one engine, one file
node nav017/site.mjs start                              # or by hand:
PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers npx playwright test -c nav017/playwright.config.mjs
NAV017_REUSE_RUNS=1 npx playwright test -c nav017/playwright.config.mjs replay.test   # re-check saved replays only
# one file at a time with its own output folder, so a wedged run never stalls or wipes the others:
NAV017_WORKERS=1 npx playwright test -c nav017/playwright.config.mjs layout.test --output test-results/nav017/out-layout
node nav017/site.mjs stop
cd ../../web && npm test && npm run lint && npm run typecheck && npm run check:glossary    # AC 45, 46
```

Environment notes (run 2):
- The site (Caddy) and the WebKit project need the **Docker daemon**. If `docker info` fails, start it (`nohup dockerd &`,
  then wait for `docker info` to answer); `site.mjs start` fails fast without it. The shared dev stack's containers come
  back on their own (restart policy); never start, stop or rebuild them.
- **Before a run, check that no earlier `nav017/run.sh`, `site.mjs` or wait loop is still alive**
  (`pgrep -af 'nav017/run.sh|site.mjs|sleep'`). A resumed agent session **replays its unfinished background commands**:
  in run 1 (observation 5) and again at the start of run 2 a replayed `run.sh` rebuilt the three outputs and re-created
  the site under a running test (the build test then saw a half-written `dist-demo-mode/` without the WASM), and a
  replayed wait loop called `site.mjs stop` three seconds into the next file. Kill such trees before starting, and run
  the files through a chain that **re-creates the site before each file** when `state.json` or the 200 on `/demo-a/` is
  missing (`NAV017_SKIP_BUILD=1 node nav017/site.mjs start`; the run-2 chain scripts do this).
- Run one file at a time with its own `--output` folder (the `run()` helper in the chain scripts), Chromium and WebKit
  in parallel at most 2 + 1 workers on the 4 vCPU container. The real-time budgets of the NAV-002/003/004 regression
  suites need the machine to themselves: run them after the NAV-017 chains, never alongside.

Environment notes (run 3, re-verification of `0b166a8`):
- `site.mjs start` always removes and re-creates the Caddy container, so when the Chromium and WebKit chains run in
  parallel only the **first** invocation may go through `run.sh` (`NAV017_ENGINES=chromium NAV017_KEEP=1`, builds and
  starts the site); every later file uses `run.sh`'s own two Playwright command lines directly, after a
  `curl` guard on `/demo-a/` (200), and calls `NAV017_SKIP_BUILD=1 node nav017/site.mjs start` only when the site is
  down. Then `node nav017/site.mjs stop` once at the end.
- The `runs/` cache holds one recording per (test, engine) and is overwritten on each execution: copy a recording out
  before re-running the same test if it is needed as evidence (run 3 §2 used the run-2 G4 recording that way).
- A per-file JSON copy must be taken from `tests/e2e/test-results/nav017-results-<engine>.json` (the reporter path is
  relative to `nav017/`), before the next invocation of the same engine.

Environment notes (run 2, completed after the container restart):
- The container restarted at about 23:05 UTC on 2026-10-01 in the middle of run 2 (commit `18cb22a` is the WIP state). The
  Caddy site container was gone while `state.json` still existed; `NAV017_SKIP_BUILD=1 node nav017/site.mjs start`
  brought it back on the same build outputs (`web/` unchanged since the build at 22:32 UTC, verified with `find -newer`).
- The completed run uses two chain scripts in the scratchpad (`qa17r3-chromium.sh`, `qa17r3-webkit.sh`): one file at a
  time, `--output test-results/nav017/r3-{c,w}-<file>`, the site guard before every file, Chromium 1 worker (replays 2)
  and WebKit 1 worker in parallel, nothing else running. Each file's JSON result is copied to `qa17r3-{c,w}-<file>.json`.
- `nav017-results-*.json` is overwritten by every Playwright invocation of the same engine; only the per-file copies are
  evidence. The `.last-run.json` files in the `r2-*` folders of the interrupted run are not results (several say
  `failed` with an empty list because the run was killed).

## 5. Interpretations and limits (recorded, not silently relaxed)

- **AC 8 "within 1 s of the first map idle":** `idle` is not observable in the production build. The test records the
  time from the last opening tile response to the picker as an annotation and fails only above 5 s. Software
  rendering on a shared 4-core container makes a 1 s budget meaningless here; the real check is the PO's iPhone.
- **AC 13 "moves to that fix … within 200 ms":** read with the allowed animation: the glide toward fix *i* starts when
  fix *i* is applied and ends one fix later (UX Design note 7). Verified by code review only (see §4).
- **AC 21 "recomputed at least every 5 s":** the shown value must equal the formatted oracle value of some moment in the
  last 5.5 s (± 35 m slack for the snapped position and Ferrostar step-distance steps of up to 30 m observed on R1).
- **AC 22 heading up:** the camera bearing is not readable in the production build (the compass is hidden during the
  replay). The puck-inside-the-uncovered-map part is tested; heading up is checked visually in the screenshots and on
  the real iPhone.
- **AC 37 safe areas:** headless engines report `env(safe-area-inset-*) = 0`; the CSS is checked statically.
- **AC 20 "passes a manoeuvre":** the first fix at least **5 m** beyond the manoeuvre, i.e. ADR-0009 §1
  `distanceAfterEndOfStep = 5` (`STEP_EXIT_M`, shared with the web through `ferrostarConfig.ts`). The Android oracle
  (`QaGpxReplayTest.bannerAdvanceProblems`) uses the same +5 m; the first version of the web oracle used +1 m and
  reported the R2 walk switches (position 5–6 m past the corner, 3 fixes at 1.4 m/s) as 2–3 s late. The Android
  harness does not run that check on the walk track at all; the web one does, with the design value.
  **Manoeuvre passed before the first fix (G4, run 3):** when the first fix is already ≥ 5 m past manoeuvre *k*, the
  banner for manoeuvre *k* + 1 is rendered inside the «Эхлэх» handler, before the recorder's mutation observer
  attaches, so no mutation exists for that switch. The oracle then takes the first 1 s record as the switch **only if
  it already shows manoeuvre *k* + 1** (or *k* + 2 after a step < 40 m); a first record that still shows the passed
  manoeuvre (the D3 behaviour) is judged by its later mutation and fails as before. Every other switch is unchanged.
- **ADR-0011 §10 licence regexes:** the upstream `LICENSE.txt` of Ferrostar 0.57.0 wraps "modification,\nare
  permitted" and "CONTRIBUTORS\n"AS IS"" (not the canonical BSD line breaks) and `THIRD_PARTY_NOTICES.md` pastes it
  verbatim, so the test matches every inter-word gap with `\s+`. The required content did not shrink: the copyright
  line, the "Redistribution and use …" sentence, all three conditions, the start of the disclaimer and its last clause
  must be present in full, and "ships no licence file" must be absent.
- **AC 26 G8 en:** the Android `G8 en` golden rows come from `g8-roundabout-car-en.json` (17 steps, `arrive` without
  a side); the demo plays the **mn** recording (18 steps: a last left turn, then arrive on the left) in both UI
  languages (story › Demo routes). Rows 26 and 27 of `G8 en` are therefore derived from the mn rows (same `t_s` and
  manoeuvre, navigation-ux §4.1 English text: "In 100 meters, turn left", "Your destination is on the left") in
