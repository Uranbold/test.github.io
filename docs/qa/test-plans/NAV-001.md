## 1. Scope

In scope: every acceptance criterion (AC 1 to 42) and every edge case in the story, plus the gateway
behaviour that `openapi.yaml` promises beyond the ACs (contract cases `CT-*`), and two cross-cutting
NFRs from the QA charter: no PII in logs and OSM attribution in the tile metadata.

Out of scope for NAV-001, as the story says: mobile/web clients, GPX navigation simulation, voice-prompt
timing, rerouting, lane/speed display, battery/CPU during a drive. No GPX fixtures are needed for this
story. They start with NAV-004/NAV-005. The browser tests below use a test-only HTML page, not a product client.

the nearest routable road. That allowance is used only where a check says so (see section 6).

## 4. Edge cases and NFRs

| Case | Test | Method |
|---|---|---|
| OSM source unreachable | EC-01: URL only, source failing: data-fetch exits non-zero with URL + HTTP status; no service healthy | M (observed in TC-01-01 attempt / section 5.4) |
| Interrupted or partial build | EC-02: kill `tiles-build` during Planetiler, then `docker compose up -d`: rebuilds, never serves a partial archive | M (section 5.5) |
| Auxiliary downloads blocked | EC-03: covered by README override keys (AC08.every_download_key_documented) and the same failure path as EC-01 | A+M |
| Docker Hub 429 | AC 7 checks | A |
| Out-of-coverage coordinates | AC 26, AC 32 | A |
| Unpaved roads | AC 19 | A |
| No search result | AC 23 | A |
| Cyrillic/Latin/typo | AC 24 info (`Sukhbaatar`, `lang=en`, `suhbaatar`) | A |
| Photon `lang` not configured | AC 27, CT10 (`lang=de` gives 400 JSON) | A |
| Port 8080 in use | TC-01-01 runs the second stack on `GATEWAY_PORT=18080` | M |
| One upstream down | AC 34 | A |
| No PII in logs | LOG01: route (POST and `GET ?json=`), search, reverse and an error request with marker coordinates/text, then grep gateway, valhalla and photon logs | A (`logs`) |
| OSM attribution | AC10.attribution_osm + info on the full string; clients render "© OpenStreetMap contributors" themselves (NAV-002) | A |

Contract extras (`checks.py full`, `CT01`-`CT15`): 404/405/413 JSON bodies, HEAD tiles, `If-None-Match` gives 304,
`Accept-Ranges` on 206, no gzip on tiles, 416 beyond EOF, `GET /v1/route?json=`, unsupported `lang` 400,
`limit` capped at 20, 204 preflight on `/v1/reverse` and `/health`, Expose-Headers on preflight, `Vary: Origin`.
`contract.py` validates every documented operation's responses against the component schemas and fails on
undocumented statuses. A negative control (wrong schema) must fail.

## 5. Procedures for the manual/scripted cases

Run from the repository root unless noted. Examples use the default project; the cold/rebuild tests use a
second project (`-p navmn-qa`, port 18080) in a scratch copy so the main stack keeps running.

5.1 Automated suite against a healthy stack
```sh
tests/smoke/run.sh                                                  # AC 40-42
python3 tests/api/nav001/checks.py --group full --group perf        # AC 9-30, 32, 33, 35-38 + CT
python3 -m venv tests/.venv && tests/.venv/bin/pip install -r tests/api/requirements.txt
tests/.venv/bin/python tests/api/nav001/contract.py                 # openapi.yaml conformance
python3 tests/api/nav001/static_checks.py                           # AC 3, 6, 7, 8
python3 tests/api/nav001/checks.py --group logs --group stats --group outage --compose-dir backend   # LOG01, AC 39, AC 34
(cd tests/e2e && npm ci && npx playwright test nav001)              # E2E-01..05
```
5.2 AC 1 / AC 39 peak: copy `git ls-files -co --exclude-standard backend` to a scratch dir, `cp .env.example .env`,
set only the environment-specific keys (proxy CA, port), `docker compose -p navmn-qa up -d`, poll
`docker compose ps` every 5 s, sample `docker stats` every 2 s.

5.3 AC 2: `docker compose down && docker compose up -d`, poll health every 0.5 s, `docker compose logs tiles-build valhalla-build photon-import | grep reused`.

5.4 AC 4: in `.env` set `OSM_PBF_URL=https://unreachable.invalid/ub.osm.pbf` and `OSM_PBF_FILE=<pbf>`, then `make rebuild-data COMPOSE="docker compose -p navmn-qa"`; check exit 0, `docker compose logs data-fetch`, smoke.

5.5 AC 5 / EC-02: set `OSM_PBF_URL` to a different extract (full Mongolia) with `OSM_PBF_FILE=` empty, run `make rebuild-data`; while Planetiler runs, `docker kill navmn-qa-tiles-build-1`; then `docker compose up -d` again and check the tiles are rebuilt, not reused; compare `data/build-info.json` fingerprints and run the full suite against the new build.

5.6 AC 41: `docker compose stop photon; tests/smoke/run.sh; echo $?; docker compose start photon`.

5.7 AC 31: `CORS_ALLOWED_ORIGINS=http://localhost:5173 docker compose up -d --no-deps --wait gateway`, run
`checks.py --group cors-allowlist` and `E2E_EXPECT_ALLOWLIST=http://localhost:5173 npx playwright test nav001`,
then `docker compose up -d --no-deps --wait gateway` to restore.

## 6. Interpretations used by the suite (confirm with BA)

1. **AC 14, 100 m.** The check is strict against the story coordinates. If an endpoint is between 100 and
   150 m away, the story's 50 m move allowance is applied and a `.move` INFO line is printed. That is the
   same as the backend's 150 m reading, but it is visible in the output. Measured: the auto route starts 106 m
   from P1 (the square itself is not drivable), so AC14.first_point passes only with the allowance.
2. **AC 32 point.** X1 while the tile bounds do not cover Erdenet; X2 (Beijing) otherwise, recorded as INFO.
3. **AC 16.** Checked as written. Street names from OSM already contain ө/ү, so the suite also reports whether
   ө/ү appear in the announcement text with the street names removed.
4. **AC 17.** "Street names taken from OSM" = step `name`, `ref`, `destinations`, `exits`, `rotary_name` and the
   text components of banner instructions.
5. **AC 1 "no manual steps".** Environment-only overrides that any developer behind the same proxy would
   need (`EXTRA_CA_CERT`, local `OSM_PBF_FILE` when the source is unreachable) are allowed and recorded.

## 7. Entry and exit criteria

- Entry: `docker compose ps` shows gateway, valhalla and photon healthy; `data/build-info.json` exists.
- Exit (story accepted): every AC case above passes on the **default dev configuration**, with no open
  `blocker` or `major` defect. INFO values are recorded in the run report or the QA handoff.
