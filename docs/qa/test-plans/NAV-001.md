## 1. Scope

In scope: every acceptance criterion (AC 1 to 43) and every edge case in the story, plus the gateway
behaviour that `openapi.yaml` promises beyond the ACs (contract cases `CT-*`), and two cross-cutting
NFRs from the QA charter: no PII in logs and OSM attribution in the tile metadata.

Out of scope for NAV-001, as the story says: mobile/web clients, GPX navigation simulation, voice-prompt
timing, rerouting, lane/speed display, battery/CPU during a drive. No GPX fixtures are needed for this
story. They start with NAV-004/NAV-005. The browser tests below use a test-only HTML page, not a product client.

Contract extras (`checks.py full`, `CT01`-`CT15`): 404/405/413 JSON bodies, HEAD tiles, `If-None-Match` gives 304,
`Accept-Ranges` on 206, no gzip on tiles, 416 beyond EOF, `GET /v1/route?json=`, unsupported `lang` 400,
`limit` capped at 20, 204 preflight on `/v1/reverse` and `/health`, Expose-Headers on preflight, `Vary: Origin`.
CT08 now derives the 416 range start from HEAD `Content-Length` (`CT08.range_beyond_416`) and keeps the far range as
`CT08.range_far_beyond_416`. **CT16** (openapi.yaml 0.2.0 CORS rule): no `Access-Control-*` header repeated on 14 response kinds
(tiles 206/HEAD 200/304/405/preflight, health, unknown 404, route 200/400/405/413, search 200/400, reverse 200).
**CT17** (`--group tiles-missing`, gateway started without the archive): TILES 404 is JSON `NotFound` with single CORS
headers on GET and HEAD. It guards the error_page inheritance trap of the AC 43 fix (ADR-0002 Amendment 2).
`contract.py` also fails any case with a repeated `Access-Control-*` header.
**CT-R22** (INFO, openapi 0.4.0): compares the live `Access-Control-Expose-Headers` on the tiles 206 with the tokens in the spec's
`AccessControlExposeHeaders` example (0.4.0 says it "always includes" `Retry-After`). It is INFO, not a gate, because NAV-001 AC 30 only
requires `Content-Range`, `Content-Length` and `ETag`, and `Retry-After`/429 belong to NAV-008 (AC 13). It turns into a NAV-008 check when
that story's gateway work is tested.
`contract.py` validates every documented operation's responses against the component schemas and fails on
undocumented statuses. A negative control (wrong schema) must fail.

## 5. Procedures for the manual/scripted cases

Run from the repository root unless noted. Examples use the default project; the cold/rebuild tests use a
second project (`-p navmn-qa`, port 18080) in a scratch copy so the main stack keeps running.

5.1 Automated suite against a healthy stack
```sh
tests/smoke/run.sh                                                  # AC 40-42
python3 tests/api/nav001/checks.py --group full --group perf        # AC 9-30, 32, 33, 35-38 + CT
python3 -m venv tests/.venv && tests/.venv/bin/pip install -r tests/api/requirements.txt
tests/.venv/bin/python tests/api/nav001/contract.py                 # openapi.yaml conformance
python3 tests/api/nav001/static_checks.py                           # AC 3, 6, 7, 8
python3 tests/api/nav001/checks.py --group logs --group stats --group outage --compose-dir backend   # LOG01, AC 39, AC 34
(cd tests/e2e && npm ci && npx playwright test nav001)              # E2E-01..05, E2E-07 (E2E-06 skipped); the config has no webServer, nothing listens on :5173
```
5.2 AC 1 / AC 39 peak: copy `git ls-files -co --exclude-standard backend` to a scratch dir, `cp .env.example .env`,
set only the environment-specific keys (proxy CA, port). The OSM source stays at the default (Mongolia mirror), so the
~70 MB PBF and the ~2.4 GB of Planetiler auxiliary sources are downloaded inside the 30 min, `docker compose -p navmn-qa up -d`, poll
`docker compose ps` every 5 s, sample `docker stats` every 2 s.

5.3 AC 2: `docker compose down && docker compose up -d`, poll health every 0.5 s, `docker compose logs tiles-build valhalla-build photon-import | grep reused`.

5.4 AC 4: in `.env` set `OSM_PBF_URL=https://unreachable.invalid/ub.osm.pbf` and `OSM_PBF_FILE=<pbf>`, then `make rebuild-data COMPOSE="docker compose -p navmn-qa"`; check exit 0, `docker compose logs data-fetch`, smoke.

5.5 AC 5 / EC-02: set `OSM_PBF_URL` to a different extract (full Mongolia) with `OSM_PBF_FILE=` empty, run `make rebuild-data`; while Planetiler runs, `docker kill navmn-qa-tiles-build-1`; then `docker compose up -d` again and check the tiles are rebuilt, not reused; compare `data/build-info.json` fingerprints and run the full suite against the new build.

5.6 AC 41: `docker compose stop photon; tests/smoke/run.sh; echo $?; docker compose start photon`.

5.7 AC 31: `CORS_ALLOWED_ORIGINS=http://localhost:5173 docker compose up -d --no-deps --wait gateway`, run
`checks.py --group cors-allowlist` and `E2E_EXPECT_ALLOWLIST=http://localhost:5173 npx playwright test nav001`,
then `docker compose up -d --no-deps --wait gateway` to restore.

5.8 AC 43 negative control and CT17 (gateway only, no Valhalla/Photon needed):
```sh
git show <pre-fix rev>:backend/gateway/templates/default.conf.template > $OLD/default.conf.template
tests/api/nav001/isolated-gateway.sh start qa-gw-old 18181 $OLD backend/data
python3 tests/api/nav001/checks.py --base-url http://localhost:18181 --group ac43       # must FAIL (duplicated CORS, HTML)
(cd tests/e2e && BASE_URL=http://localhost:18181 npx playwright test nav001 -g E2E-07)  # must FAIL (TypeError)
tests/api/nav001/isolated-gateway.sh start qa-gw-missing 18182 backend/gateway/templates $EMPTY_DIR
python3 tests/api/nav001/checks.py --base-url http://localhost:18182 --group tiles-missing  # must PASS
tests/api/nav001/isolated-gateway.sh stop qa-gw-old; tests/api/nav001/isolated-gateway.sh stop qa-gw-missing
```
Mutation check for CT17: remove the tiles location's `error_page 404 = @not_found;` from a copy of the template;
CT17 must then fail (`content_type_json`, `json_not_found`).

## 6. Interpretations used by the suite (confirm with BA)

1. **AC 14, 150 m.** *Confirmed in the story (CR 2026-09-29, orchestrator's recommendation, PO did not object and
   may revise).* Hard limit 150 m = 100 m route-end limit + 50 m allowed point move; 100-150 m passes and prints a
   `.move` INFO line. Measured on Mongolia: the auto route starts 106 m from P1 (the square is not drivable) and ends
   49 m from P3. If the PO chooses a strict 100 m, AC14.first_point_near_P1 fails.
2. **AC 32 point.** *Confirmed in the story.* X1 while the tile bounds do not cover Erdenet (BBBike build); X2
   (Beijing) otherwise, recorded as INFO. The Mongolia tile bounds are a rectangle that also contains Beijing, but
   the routing graph has no roads there, so X2 still gives a 4xx.
3. **AC 16.** Checked as written. Street names from OSM already contain ө/ү, so the suite also reports whether
   ө/ү appear in the announcement text with the street names removed.
4. **AC 17.** "Street names taken from OSM" = step `name`, `ref`, `destinations`, `exits`, `rotary_name` and the
   text components of banner instructions.
5. **AC 1 "no manual steps".** Environment-only overrides that any developer behind the same proxy would
   need (`EXTRA_CA_CERT`, local `OSM_PBF_FILE` when the source is unreachable) are allowed and recorded.

6. **AC 6 and the NAV-002 glyph files.** AC 6 literally says `git ls-files | grep -Ei '\.(osm\.pbf|pbf|pmtiles|mbtiles)$'`
   shows nothing. ADR-0004 commits 768 MapLibre glyph range files (`web/public/fonts/Noto Sans */<n>-<m>.pbf`, SIL OFL,
   14 MB) that match that grep but are font assets, not OSM data or build output. The suite exempts exactly that path
   pattern and reports it as INFO. *BA asked to reword AC 6 (e.g. "no OSM extract, tiles archive, routing graph or search
   index", or exclude `web/public/fonts/`).* If the BA keeps the literal wording, AC 6 fails and ADR-0004 needs revisiting.
7. **AC 12 under D1.** The default build is judged; the optional BBBike build has no size limit (story AC 12) and is not
   checked. The run records the measured size in the INFO line.

## 7. Entry and exit criteria

- Entry: `docker compose ps` shows gateway, valhalla and photon healthy; `data/build-info.json` exists.
- Exit (story accepted): every AC case above passes on the **default dev configuration**, with no open
  `blocker` or `major` defect. INFO values are recorded in the run report or the QA handoff.
