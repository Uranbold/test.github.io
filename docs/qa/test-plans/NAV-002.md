## 1. Scope

In scope: all 50 acceptance criteria and the story's edge cases that apply to a map-only client (GPS lost,
permission denied, unsupported API / insecure origin, no network, gateway down or rebuilding, archive
replaced, CORS, empty areas, missing glyph ranges, 320 px screens, language switched while a message is open).
Also R2 (share of non-Cyrillic labels) is recorded as information.

Out of scope, as the story says: search, routing, guidance, voice, rerouting, GPX simulation (no route
exists in NAV-002, so **no GPX fixtures** are added), battery/CPU drive, browsers other than desktop
Chromium, hosting. **No API tests** are added: NAV-002 changes no contract, and the tiles endpoint it uses is
covered by the NAV-001 suite (`tests/api/nav001`, E2E-01/02).

### Failure simulation (client side only, story "Test approach")
- Closed port: dev server 5174 with `VITE_GATEWAY_BASE_URL=http://localhost:59999`.
- Request interception on `**/tiles/basemap.pmtiles`: abort, 404, 500, 502, 503, HTML body with 200 or 206, delays (loading state), a forwarded response with a changed `ETag` (AC 42).
- `context.setOffline(true/false)`.
- Geolocation: Playwright permissions and positions; `setGeolocation(null)` gives `POSITION_UNAVAILABLE`. For the 10 s timeout a stub fires `TIMEOUT` after `options.timeout`, as a browser without a fix does. For AC 24 `Navigator.prototype.geolocation` is deleted, and the insecure origin is `http://nav002-lan.test:5173` forwarded by the test to the dev server.
- AC 3: nothing listens on 8081. The test forwards 8081 to the real gateway inside the browser context, so every tile request can be seen, and none may reach 8080 directly.
