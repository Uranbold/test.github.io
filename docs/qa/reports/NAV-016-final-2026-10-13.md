### Story / design alignment
- **Q-1 (AC 29 wording, business-analyst):** the story says the duration check runs on "the stub pack in CI" with the
  limits applied. ADR-0010 §7 (accepted) says the stub model only reports and the real pack is enforced, and the code
  does that. QA treats ADR-0010 §7 as the intended behaviour, because the stub is a 70 ms-per-character tone model, not
  speech. The AC text should be aligned (for example: "with the stub manifest the check reports only; with a real pack
  it fails"). This is a technical alignment, not a product decision. If the BA sees it differently, it goes to the PO.

- **Q-2 (AC 8 scan definition, architect):** the clarified definition lists `$NAME` / `${NAME}` *values* as
  references, but says nothing about the variable name itself inside a parameter expansion. `${CHIMEGE_API_TOKEN:-}` in
  `backend/tools/voice-pack/run.sh:80` gives the "value" `-}` under the literal rule. QA treats "name inside `${…}`" as a
  reference. Please confirm that in B10, so the backend's `test_repo.py` and the QA scan implement the same rule.

### Risks for the first real pack (not defects)
- **R-1 (AC 29):** the longest domain prompts are double roundabout chains at catch-up prefixes, for example
  `dist.m.650 + instr.roundabout.exit.6 (nonFinal) + join.then + instr.roundabout.exit.6`. navigation-ux §4.7 estimates
  6.2–6.9 s for real speech, while the stub model gives 8.5 s. If real Chimege segments are slower than the estimate
  (phrase-final lengthening per clip), `checkVoicePackDurations` will refuse the demo build. Check the generator's
  `review/prompts.tsv` (B11) right after the PO's first real run, before building.

## 6. Reported flaky test: `QaNav011ActivityTest.tcA13`

- **Likely root cause** (code reading, for the mobile engineer if it shows up again):
  - `FakeGateway.urls` (`mobile/android/app/src/test/java/mn/navmn/app/android/TestAppModule.kt:41`) is a
    `Collections.synchronizedList`.
  - `QaNav011ActivityTest.reverseUrls()` (line 194) iterates it with `filter { … }` without `synchronized(urls)`.
  - When the OkHttp interceptor thread appends a URL during that iteration, the result is a
    `ConcurrentModificationException`.
  - Fix: `synchronized(FakeGateway.urls) { FakeGateway.urls.filter { … } }`, or a `CopyOnWriteArrayList`.
