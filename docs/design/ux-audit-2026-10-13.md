# UX audit 2026-10-13: web demo and Android app

- **Owner:** ux-designer. **Requested by:** PO, 2026-10-13 ("check better UI/UX design and UI/UX laws with the demo and app").
- **Scope:** (a) the web demo as built: the normal build (`web/dist`, NAV-002 map, NAV-003 search, NAV-004 route preview, gateway mocked with the QA fixtures) and the demo-mode build (`web/dist-demo-mode`, NAV-017 picker, replay, arrival); (b) the Android app as specified and as coded (`mobile/android/app/src/main/java/mn/navmn/app/ui/**`, `src/demo/**`), measured from the Compose code and `tokens.json`; no emulator in this container.
- **Yardsticks:** the UX laws and Nielsen heuristics of the design principles (Fitts, Hick, Miller, Jakob, Doherty, Gestalt, Von Restorff, serial position, Tesler, Postel, peak–end, goal gradient, Zeigarnik, cognitive load), NHTSA driver-distraction guidance (one glance ≤ 2 s, no typing while moving), WCAG 2.2 AA (4.5:1 text, 3:1 large text and non-text, 2.5.8 target size, 2.4.7 focus, 1.3.1 / 4.1.2 names and roles), Material 3 and the 48 dp / 44 pt touch rules, Mongolian-first text length.
- **Evidence:** screenshots, DOM measurements and axe-core runs in the session scratchpad (`shots/*.png`, `audit-web-*.json`, `audit-*.log`); the script is kept as [`prototypes/audit-web.mjs`](prototypes/audit-web.mjs) so the run can be repeated (README). `check-contrast.mjs` → all checks passed. Numbers are quoted per finding; file:line references point at the code as of commit `git log -1` 2026-10-13 09:57.

## 1. Summary

The product is in good shape on the hard, measurable rules: **every interactive element measured on the web (168 audited states) is ≥ 44 × 44 CSS px (all buttons 48 × 48; the only 44 px target is the attribution link, by design), 0 overlapping controls outside scrolled lists, 0 missing accessible names, 0 contrast failures on enabled text in day and night, smallest text 12 px, axe-core 0 serious or critical issues on 13 audited states, a logical Tab order with visible focus on every stop, Mongolian strings wrap and never clip in the states exercised.** The Android code follows the same tokens (48 dp controls, 8 dp gaps, 56 dp rows, capped overlay type), and the specs since NAV-005 carry measured layout evidence and a design rationale.

The findings below are therefore mostly about **second-order** rules: the hierarchy of numbers a driver glances at, error prevention around the one destructive control on the guidance screen, two Mongolian-typography details (orphaned politeness particle, one-line names on Android), a few WCAG robustness points, and three product-level choices the PO should make (time-left-first panel, system colour scheme on the web, an undo for «Дуусгах»). Nothing found is a release blocker; one item (UX-01) is rated high because it touches driving safety.

Counts: **22 findings** (1 high, 7 medium, 14 low); 3 pure spec fixes applied in this audit (section 5); everything else is a proposal with an owner.

### What was checked and passed (no finding)

- **Touch targets:** web, 168 audited states (49 demo-mode + 2 arrival + 91 normal build + 26 extra): 0 targets below 44 px; the 44 px one is the attribution link; buttons 48 × 48, list rows ≥ 56 px, «Эхлэх» 56 px, route tabs 48 px. Android code: `MapIconButton` 48 dp, `IconButton.size(48.dp)`, `heightIn(min = 48/56.dp)` on every row and button, `Spacer(8.dp)` between controls, `HandleZone` 48 dp (not the 24 dp of the spec, on purpose). Gaps < 8 px on the web occur only inside grouped controls (zoom + / −, adjacent list rows, tabs), as designed.
- **Contrast:** 0 failures on enabled text in day and night (every text/background pair resolved against an opaque surface; the only < 4.5:1 texts are the disabled «Эхлэх» / "Start", exempt under WCAG 1.4.3 inactive). `check-contrast.mjs`: all token pairs and 86 map-style values pass.
- **Names and roles:** 0 unnamed controls on the web; Android buttons have `contentDescription` from resources, lists `collectionInfo`, radios `selectable(role)`, the sheet `paneTitle`, live regions polite only.
- **Keyboard:** Tab order on the web = DOM order = reading order (search → top-bar buttons → results or card → map canvas → bottom controls → attribution; route panel: close → fields → swap → selected tab → switch → turn list); Escape closes the panel; focus never lands on `body` except after the last stop; focus rings 2 px `ui.focus-ring` on every stop (the search input and route fields draw it on the field container).
- **axe-core:** 0 serious / critical on 13 states (picker, guidance day and night, arrival, ready, results, place card, route result, coordinate card, location denied, tiles unavailable); the only rule hit is `region` (UX-08). The picker state has 0 violations of any level.
- **Text size:** smallest 12 px (attribution, scale bar, captions); banner distance 32 px bold, instruction 24 px, street 18 px; at text zoom 200 % the web guidance switches to the stacked banner and keeps ≥ 80 px of map (screenshot 006). Android overlay cap 1.3 (distance 1.2) measured in the NAV-005 checker.
- **Mongolian text:** no clipped string in any audited state; the longest banner «Баруун талын гарах зам руу эргэнэ үү» takes 2 lines at 360–412 dp. Message texts wrap, buttons never wrap (labels ≤ 20 characters).
- **Driver safety rules:** no text field on the guidance screen; typing lock from 15 km/h on S1/S3 with a passenger override (NAV-011); automatic reroute, retry and recovery without taps; recenter auto-resume 15 s; «Дуусгах» far from the recenter; voice notice never covers «Дуусгах»; attribution never covered (every screenshot).
- **State coverage:** loading, empty, error, offline, GPS lost, permission denied, unavailable and static-demo states exist for every screen with glossary copy (NAV-002/003/004/005/017 state tables; verified on the web for offline, no results, tiles unavailable, routing unavailable, no route, location denied).
- **Jakob's law:** search on top, bottom sheet preview, long-press for a point, green banner top / progress bottom / puck at 70 %, recenter bottom-left, radio list of routes, M3 tabs, switch rows, extended FAB: all Google Maps / Material placements.
- **Doherty threshold:** every wait has a budget in the specs (300 ms loading rows, 400 ms selection, 700 ms camera, 1 s banner); the web picker and preview answer the first tap within one frame (optimistic selection, loading row after 300 ms).
