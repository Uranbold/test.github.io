# Security review: NAV-016 Mongolian voice clip pack, 2026-10-13

Scope: the Verify-stage security and privacy review of NAV-016 (`docs/requirements/stories/NAV-016-mongolian-voice-clip-pack.md`) and ADR-0010 (§4.5 custody), commits `653db4d..4a64023`. Later commits on the branch were read only where they change the contract (`6348792`, architect integration review). Covered: the build-time generator `backend/tools/voice-pack/` (Chimege token handling, retries, cache, review page), its image and Python dependencies, the Gradle build-time pack guard (`buildSrc`), the Android runtime validator, decoder and fallback, the web port (text only), and custody of clips and the token (D79, D180, D228, AC 53).

Method: static review, plus local checks only. The tests ran in the digest-pinned generator image with `--network none`, against the local fake vendor server. Mutation tests and probes ran on scratch copies outside the repository. **No request was sent to the vendor**, and no external or production host was probed. Public registries (Docker Hub, PyPI, Google Maven, OSV) were read for digests and advisories only. Done by the `security-engineer` role.

## Result

- **No critical or high finding in the code.** Findings: medium 1 (VP-8, the exposed token, which is a process issue and not a code issue), low 5, info 5.
- The token prefix given by the orchestrator appears **0 times** in the working tree (tracked, untracked and ignored files), in the history of every ref, and in every git object, unreachable objects included. It also appears 0 times in the session scratchpad and in the debug APK on disk. It **does** appear outside the repository on the agent machine (VP-8). This report never quotes the value or its prefix.
- **No audio, pack manifest or review file has ever been added on any ref.** The ignore rules cover the generator's output paths and `mobile/android/voicepack-local/`. CI never calls the vendor.
- Token handling meets ADR-0010 §4.2. The token is read from the environment only, sent only in the `token` header, never follows a redirect, and an override is accepted only for a loopback host. It is absent from the cache key, cache file names, cache index, manifest and review files. Docker gets it by name only. The AC 9 sentinel test passes, and it does catch a first-line leak (mutation test M1). The redaction layer itself is never tested (VP-1).
- Supply chain: both image digests match Docker Hub, and every pip hash matches PyPI. OSV lists no advisory for the six Python packages or for `androidx.test:runner:1.5.0`. The runner's `.aar`/`.pom` sha256 in `verification-metadata.xml` match Google Maven, and the runner is on the `androidTest` classpath only.
- Android: the pack is an APK asset, so the APK signature is its trust root. The validator still checks V1–V10, rejects path traversal, and bounds every buffer through `durationMs`. Any decode or playback error, including `Error`s, falls back to the chime. No manifest, permission or exported-component change.
- Privacy: no route-derived data leaves the device for voice. The generator sends the vendor only inventory spoken texts plus the `nonFinal` carrier (test `test_only_inventory_text_and_carrier_are_sent`). The vendor never receives personal data.

Severity gates (`.claude/agents/security-engineer.md`): critical/high block the story; medium must be fixed before a public release; low/info go to the backlog. In workflow review schemas: medium → `major`, low/info → `minor`.

## Evidence and fixes

### VP-8 Exposed token outside the repository (medium)
- Evidence: the orchestrator searched for the prefix with `grep -rIl` and `git log --all -S` / `-G`, plus a pass over every blob from `git cat-file --batch-all-objects`. Result: 0 in the working tree, history and objects. A `grep -rl` over the session scratchpad also gave 0. A filename-only `grep -rl` over the agent's home and `/tmp` found 3 files: two Claude session transcripts (main session and one subagent) and one local tool log. No file content was printed. The exact paths went to the orchestrator in the handoff and are not repeated here.
- Fix:
  - The PO gets a new token from the vendor and confirms that the old one is revoked. Until then, no real pack is built with the old token.
  - Optionally, after rotation, the PO deletes the local copies.
  - Architect: ADR-0010 §4.5 should say that the token is never pasted into a chat or an issue. In an agent session it is exported in the shell before the session starts (`read -rs`, README "The token"). Better still, real packs are built on the PO's machine only.

### VP-1 Redaction layer untested (low)
- Evidence: two mutants were run in scratch copies with `docker run … --network none -v <copy>:/repo/backend/tools/voice-pack:ro navmn-voice-pack:1.0.0 python -m unittest tests.test_chimege.SentinelTest.test_sentinel_all_scenarios`.
  - **M1, first line broken** (the token is put into the 4xx error text, `chimege.py:189`): `FAILED (failures=2)`, scenario 401. With redaction on, stderr was clean (the layer works) and the test failed on the exception text. With redaction off, it failed on stderr. So the test does catch a leak.
  - **M2, `register()` turned into a no-op** (`redact.py:20–26`): `OK`. No test notices that the second line is gone.
- Fix: add a test that drives `main()` with a `synth_factory` that raises `RuntimeError(SENTINEL)` after `read_token`, then asserts that stdout, stderr and the `--log` file show `[redacted]` and not the sentinel. Add a direct test of `RedactingStream` and `Reporter`.

### VP-2 Timeout per socket operation, no size cap (low)
- Evidence:
  - `chimege.py:136–138` uses `opener.open(req, timeout=self._timeout)` and `resp.read()`.
  - Local probe: a loopback server sent a 20-byte body one byte every 0.2 s. With `timeout=0.5` the client returned after `elapsed=3.81s  status=200`. Each `recv` resets the timer, and the body is read without a limit.
  - Impact is limited (a stalled run, Ctrl-C works, and the vendor is reached over TLS). It is a gap against AC 11 and ADR-0010 §4.2 ("a 30 s timeout each").
- Fix: an overall per-attempt deadline (monotonic clock). Read the body in chunks up to a cap (for example 8 MB; a 300-character clip is under 1 MB at 22,050 Hz 16-bit mono). A deadline or cap overrun counts as a retryable timeout.

### VP-3 D79 prevention only in two paths (low)
- Evidence:
  - `git check-ignore` reports `mobile/android/app/src/main/assets/voicepack/manifest.json` and `web/public/x.aac` as **not ignored**. The tool and `voicepack-local/` paths are ignored.
  - `tests/test_repo.py:58–64` scans only `backend/tools/voice-pack`.
  - `infra/ci/backend-static-checks.sh` runs only that scan.
  - `tests/android/nav016/qa_nav016_checks.py` `scan` is repo-wide but is not wired into CI. The root `.gitignore` has no audio patterns.
- Fix: run a repo-wide AC 19 scan in CI (tracked audio extensions other than the chime path, any tracked `manifest.json` with `inventorySha256`, any `review/index.html`). Add root `.gitignore` patterns for `*.aac`, `*.m4a`, `*.wav`, `*.opus`, `*.ogg`, `*.flac`, `*.mp3`. Push protection (SP-3) does not cover audio.

### VP-4 Build guard follows symlinks, no size cap (low)
- Evidence:
  - `VoicePackGuard.java:285–300` reads clips with `Files.readAllBytes`, and `build.gradle.kts` `BundleVoicePack` copies them with `File.copyTo`. Both follow symlinks.
  - Local harness: the three `buildSrc` classes were compiled with `javac` in scratch, and a stub pack was copied. Clip 1 became a symlink to a decoy file outside the pack, and clip 2 a symlink to a 50 MB file; their sha256 in the manifest were updated. `VoicePackGuard.check(dir, OPTIONAL, <its inventorySha256>)` returned `problem=null files=305`.
  - This needs a crafted pack directory on the build machine, so it is low.
- Fix: refuse a clip unless it is a regular file not followed through links (`Files.isRegularFile(p, NOFOLLOW_LINKS)`), and its real path stays under the pack directory. Cap each clip (for example 256 KB) and the pack total (for example 4 MB, in line with AC 51). Also refuse a symlinked `manifest.json`. The same rule belongs in the generator's `verify` and in pack-format §8 (architect).

### VP-5 Self-asserted "real" label (low)
- Evidence:
  - `build.py` writes `vendor=synth.vendor`, which is always `chimege` for `ChimegeSynthesiser`, whatever `--api-base` says (`chimege.py:96`, `:102–103`).
  - The sentinel success scenario produces a complete pack from the fake server's tones.
  - The demo build on this machine bundled a placeholder pack (random bytes, `vendor` `chimege`, written by a QA helper script in the scratchpad), and the guard accepted it.
- Fix:
  - Backend: when `--api-base` is set, write `source.vendor = "stub"` (or refuse to write a pack outside a test directory).
  - Architect: decide whether the schema needs an explicit test marker.
  - Release check: the bundled manifest SHA-256 equals the listened pack's (checklist C22).

### VP-6, VP-7 Hygiene (info)
- VP-6:
  - Fix: pass `env` without `CHIMEGE_API_TOKEN` to `subprocess.run` (`codec.py:146–173`, `cache.py:106`) and to the process pool, or remove the variable from `os.environ` after `read_token`.
  - Docker: `-e NAME` still puts the value in the container config. That is accepted on a single-user machine.
- VP-7:
  - Fix: let `ssl.SSLCertVerificationError` (inside `URLError.reason`) fail at once with "TLS certificate not trusted".
  - Print `Error-Code` only if it matches `^[0-9A-Za-z-]{1,16}$`, otherwise print "invalid Error-Code".

## Not verified

- A real vendor run, a real pack, and the vendor's TLS and redirect behaviour. No request was sent to the vendor.
- The instrumented decode test (`ClipDecoderInstrumentedTest`) on a device or emulator, and `MediaCodec` behaviour with malformed ADTS on real devices. The bytes are covered by the APK signature, so this is robustness, not a security boundary.
- `gitleaks`: not installed. Regex and prefix searches replaced it (gate A2 partial).
- A merged-manifest diff from a release build. The diff changes no `AndroidManifest.xml`.
- Whether an agent egress proxy that terminates TLS would see the token in a real agent-session build. Inferred from the proxy setup and not tested. It is another reason for VP-8's "PO machine only" option.

## Legal questions for counsel (no legal conclusion here)

1. Chimege's written output terms (AC 53): in-app redistribution of the generated clips, storage of the vendor audio cache and backups, attribution requirements (the vendor name sits in the bundled manifest, VP-9), and the data location of the synthesis service.
2. The generator sends only fixed glossary phrases (no personal data), and voice playback is local. Counsel can confirm whether the Law on Personal Data Protection (2021) has any bearing on the voice feature. Our reading of the data flow is "no personal data processed", but that is not a legal conclusion.
